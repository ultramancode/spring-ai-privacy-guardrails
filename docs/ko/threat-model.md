## 보호 대상

이 위협 모델은 라이브러리가 지원하는 개인정보 보호 경계에서 다음 정보를 보호 대상으로
봅니다.

- 모델 입력, 검색 콘텐츠, 도구 입력·결과와 최종 출력에 포함될 수 있는 원문 개인정보(PII).
- 요청별 `PrivacySession`이 관리하는 토큰과 개인정보 원문 값 사이의 매핑.
- 원격 분석 서비스에 사용하는 인증 정보와 분석 요청·응답.
- 도구마다 공개 가능한 엔티티 유형을 정의한 원문 값 공개 정책.

## 신뢰 경계

애플리케이션과 외부 모델 제공자, 원격 분석 서비스, 도구 실행 대상 사이에는 각각
별도의 신뢰 경계가 있습니다. 도구를 등록했다는 사실만으로 원문 값 공개가 허용되지는
않으며, 공개할 엔티티 유형을 도구별로 명시해야 합니다.

사용자 정의 분석기와 확장 구현은 애플리케이션의 일부로 실행됩니다. 분석기가 반환한 결과는
라이브러리가 검증하며, 확장 구현이 지원되는 개인정보 보호 경계를 통해 데이터를 주고받을
때도 같은 정책을 적용합니다. 원격 모델이나 분석 서비스를 사용하는 경우 전송 보안과 데이터
처리 방식은 각 서비스와 배포 환경의 설정을 따릅니다.

## 위협과 통제

| 위협 | 라이브러리의 통제 | 보호 범위와 고려사항 |
| --- | --- | --- |
| 개인정보가 보호되지 않은 채 모델에 전달되거나 최종 응답으로 반환됨 | 지원되는 모델 입력의 개인정보를 모델 호출 전에 보호하고, 출력 보호를 활성화하면 최종 응답에 설정한 출력 정책을 적용합니다. | 탐지 범위는 사용하는 분석기와 설정에 따라 달라집니다. 지원하지 않는 콘텐츠와 보호 경계 밖에서 이루어진 변경은 자동 보호 범위에 포함되지 않습니다. |
| 다른 요청의 토큰을 재사용하거나 유효하지 않은 세션으로 원문 값 매핑에 접근함 | 요청마다 별도의 세션에서 토큰과 원문 값 매핑을 관리합니다. 다른 요청의 토큰은 원문 값으로 복원하지 않으며, 알 수 없거나 종료된 세션은 오류로 처리합니다. | 세션 식별자는 요청별 개인정보 처리 상태를 구분하기 위한 내부 값입니다. |
| 도구가 허용되지 않은 개인정보 원문 값을 받거나 새로운 개인정보를 반환함 | 도구별 원문 값 공개는 기본 거부이며, 명시한 엔티티 유형만 실행 직전에 복원합니다. 보호된 도구의 실행 결과는 다시 검사하고 보호합니다. | 보호된 `ChatClient`의 표준 경로에서는 `PrivacyToolCallbackFactory`로 감싸지 않은 콜백을 오류로 처리합니다. 사용자 정의 도구 실행 경로는 별도로 보호해야 합니다. |
| 구조화된 값, 스트리밍 응답 또는 `returnDirect` 흐름을 통해 개인정보 검사가 우회됨 | `JSON`과 지원되는 값 구조는 크기와 복잡도 상한을 적용해 검사합니다. 출력 보호를 활성화하면 스트리밍 응답을 끝까지 모아 검사하고, `returnDirect` 결과에도 설정한 출력 정책을 적용합니다. | 인코딩되거나 압축되어 원문을 바로 읽을 수 없는 콘텐츠는 검사 전에 애플리케이션에서 텍스트나 지원되는 JSON 형태로 변환해야 합니다. |
| 분석기가 유효하지 않은 결과를 반환하거나, 여러 결과가 겹치거나, 일부 분석기가 실패함 | 라이브러리는 탐지 결과의 위치와 엔티티 유형을 검증합니다. 결과가 겹치거나 유형이 충돌하면 정해진 규칙에 따라 정리하고, 분석기 실패는 설정한 실패 정책에 따라 처리합니다. | 사용하는 분석기와 신뢰도 기준, 일부 분석기 실패 허용 여부에 따라 실제 탐지 범위가 달라질 수 있습니다. |
| 오류나 진단 정보에 개인정보가 포함됨 | 라이브러리가 생성하는 개인정보 보호 오류와 분석기 실패 알림에는 개인정보 원문 값이나 분석 서비스의 응답 내용을 넣지 않습니다. | 모델 제공자와 도구의 오류 메시지 및 SDK 로그는 각 구성 요소의 설정에 따라 관리해야 합니다. |
| 개인정보가 저장소나 다른 메모리 사본에 남음 | 표준 개인정보 보호 구성을 적용한 Spring AI 요청이 정상 완료되거나 오류·스트림 취소로 끝나면 라이브러리가 관리하는 세션 매핑을 정리합니다. 원문 값 매핑은 모델 요청이나 도구 입력에 포함하지 않습니다. | `PrivacyService`를 직접 사용하는 경우에는 애플리케이션이 각 `PrivacySession`의 수명주기를 관리하고 세션을 닫아야 합니다. 저장소에 이미 존재하는 데이터나 라이브러리 밖에서 만들어진 사본을 자동으로 변경하거나 삭제하지는 않습니다. |
| 매우 큰 입력이나 오래 걸리는 사용자 정의 분석기·도구로 인해 처리 시간과 메모리 사용이 과도하게 늘어남 | 라이브러리는 지원되는 텍스트·JSON과 `core` 값 구조, 응답을 검사할 때 크기·개수·중첩 깊이 등의 상한을 적용합니다. | 사용자 정의 분석기와 도구의 실행 시간 및 자원 제한은 애플리케이션에서 설정해야 합니다. 스트림 취소는 세션을 정리하지만 이미 실행 중인 동기식 분석기나 도구 코드를 강제로 중단하지는 않습니다. |
| 지원하지 않는 메시지나 메타데이터 또는 비텍스트 콘텐츠에 개인정보가 포함됨 | 안전하게 처리할 수 없는 `Message` 구현은 모델에 전달하지 않고 오류로 처리합니다. 지원되는 메시지의 텍스트와 라이브러리가 명시적으로 지원하는 추론 텍스트에는 개인정보 보호를 적용합니다. | 그 밖의 응답 메타데이터와 이미지·오디오 같은 비텍스트 콘텐츠는 별도로 보호해야 합니다. 미디어 제한은 데이터 크기만 확인하며 내용의 개인정보를 탐지하지 않습니다. |
| 사용자 정의 Advisor나 도구 실행 경로에서 개인정보 보호 단계가 누락됨 | 라이브러리의 표준 개인정보 보호 구성을 적용한 `ChatClient`에서는 필수 Advisor의 누락·중복과 보호되지 않은 도구 콜백을 확인합니다. | 개인정보 보호 경계 밖에서 데이터를 변경하는 Advisor나 사용자 정의 `ToolCallingManager`·`ToolCallbackResolver`를 사용하는 별도 실행 경로는 애플리케이션에서 보호해야 합니다. |

정확한 정책과 처리 상한은 [설정](configuration.md)을 참고하세요.

## 중요한 한계

개인정보 보호는 라이브러리가 지원하는 경계에서 동작하며, 설정한 분석기가 탐지한 콘텐츠에
적용됩니다. 따라서 모든 민감한 값을 항상 탐지하거나 분류한다고 보장하지는 않습니다.

토큰과 `PrivacyContextHandle`은 요청별 개인정보 매핑을 가리키는 내부 식별자입니다.
인증 수단이 아니며, 토큰화된 데이터가 익명화됐다는 의미도 아닙니다. 세션 정리는
라이브러리가 보유한 매핑을 해제하지만, 다른 구성 요소가 이미 보관한 문자열이나 사본까지
삭제하지는 않습니다.

일부 분석기의 실패를 허용하도록 설정하면 성공한 분석기의 결과만으로 요청 처리를
계속합니다. 이 경우 탐지 범위가 줄어들 수 있습니다. 자세한 내용은
[설정](configuration.md#탐지와-해석)을 참고하세요.

## 별도로 관리할 영역

이 위협 모델은 라이브러리가 지원하는 `core` 직접 사용 경계와 Spring AI 연동 경계에서의
개인정보 처리를 다룹니다. 다음 항목은 애플리케이션과 배포 환경에서 별도로 관리해야 합니다.

- 프롬프트 주입과 모델 콘텐츠 안전성.
- 애플리케이션·호스트 보안, 사용자 접근 권한과 도구 호출 권한, 저장소 접근 제어,
  네트워크 보안과 로그 관리.
- 모델·분석 서비스의 데이터 보존 정책과 법률·규제 준수.
